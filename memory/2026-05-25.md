## Bug Root Cause
- The previous skill body only described a single-paper execution path, so a user passing multiple papers could cause the coordinator to process them serially in one context instead of isolating work per paper.

## Key Decisions
- Use one worker per paper; never combine multiple papers into one worker to reduce worker count.
- Use a replenishing worker pool with up to six concurrent workers for large batches, immediately starting the next pending paper whenever a worker finishes.
- Keep each worker context isolated with only its own `paper_spec`, scratch directory, vault path, and global constraints.
